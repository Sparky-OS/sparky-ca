# Ed521 verification provider prototype

This OpenSSL 3 provider follows **Pedro F. Albanese's e521 reference**:
https://github.com/pedroalbanese/e521 (upstream `4a89f91`). Pedro is the
original implementation's author. The C public-operation port uses his
curve constants, Edwards addition and point encoding, with interoperability
and input-validation fixes measured against ITI's real AC Raiz v7 and an
independent affine Python oracle. The local Go fixes precede this prototype.

ISC preserves his permissive licensing and is compatible with Apache-2.0
and the surrounding GPL-3.0-or-later application. This subdirectory is ISC;
the rest of sparky-ca retains its existing license and copyrights.

The provider supports PureEd521 with empty context, public-key import and
DER SubjectPublicKeyInfo decoding. Load it alongside OpenSSL's default
provider. It handles **no private keys, key generation or signing**. The
affine BIGNUM arithmetic is variable-time and has not been independently
audited. This is an interoperability prototype, not a production crypto
library or an upstream-approved algorithm. Ed521ph X.509 support awaits an
authoritative numeric OID and parameters; no number is guessed here.

Build inside an isolated container:

```sh
cmake -S ed521-provider -B build-provider -G Ninja
cmake --build build-provider -j4
ctest --test-dir build-provider --output-on-failure
```

The application build also exposes an opt-in `-DBUILD_ED521_PROVIDER=ON`.
Its default remains off, and the prototype is not installed by CMake.
Provider integration rejects signature/message/key mutations and checks a
three-level independently generated chain. Provider constraints reject ten
malformed or small-order SPKIs and assert signing/key generation are unavailable.
The application test checks actual v7 capability, a verified intermediate,
failure without the provider, altered signatures, unpinned roots, incorrect
bundle hashes and install/remove in a redirected system store.

Example configuration (use an absolute module path):

```ini
openssl_conf = init
[init]
providers = provider_sect
[provider_sect]
default = default_sect
ed521-provider = ed521_sect
[default_sect]
activate = 1
[ed521_sect]
module = /absolute/path/ed521-provider.so
activate = 1
```

Set `OPENSSL_CONF` to that file before starting the application. Test
`openssl verify -check_ss_sig -CAfile v7.pem v7.pem`: accepting a pinned
root without `-check_ss_sig` does not prove signature verification. The
provider changes signature capability, not which roots an application trusts.
It does not give NSS, Java, browsers or Okular Ed521 support.

Public fixtures in `tests/data` include ITI v7 and a synthetic three-level
chain generated by the independent oracle in the patched e521 repository.
Synthetic public seeds are documented there. They are never personal keys.
No certificate issued by real v7 was found in either published ITI archive.
